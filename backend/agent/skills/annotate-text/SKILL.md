# 高亮与笔记：`Highlight └── Note`

两件事一起管：**高亮**是"用户在某一面上标出来的一段文字"，**笔记**是挂在某条高亮上的正文。
关系固定 —— 笔记的锚点就是那条高亮，所以**没有孤儿笔记**：要写笔记，先有高亮。

## 什么时候用

- "把第 3 页那段 `Attention Is All You Need` 标成黄色" → `highlight_manage op=create`
- "这段加个笔记：这里其实是……" → 先确认/建立高亮，再 `note_manage op=create`
- "我标过哪些？""这篇的笔记都有什么？" → `op=list`
- "我记过关于 X 的笔记吗？""哪条笔记里提到过 XX？" → `notes_search(query="XX")`（**选中原文与笔记正文都会命中**）
- "别的论文里我记过这个吗？" → `notes_search(query="XX", scope="all")`
- "这条笔记对应原文哪里？""跳到那处高亮" → `op=locate`
- "把那处高亮删了""笔记内容改成……" → `op=delete` / `op=update`（**用户明确说了才做**）

**不要**因为"这段话很重要"就自己去标：标注是用户的动作，你只在被要求时做。

## 三面锚点：先说清"标在哪一面"

| `anchor` | 是什么 | 例子 |
|---|---|---|
| 正文行 id | 阅读器里那一行（原文/译文对照的一行） | `p004-02` |
| `md:p<页号>` | Markdown 视图里那一页 | `md:p4` |
| `pdf:p<页号>` | 原 PDF 的页图 | `pdf:p4` |

**行 id 只有一处拿得到**：`figure_list` 回执里每条图形的 `anchor`（= 图注所在那一行的行 id，
如 `p008-02`）。要在图注上标高亮/写笔记，就把它**原样**传给 `highlight_manage` / `note_manage`。
除此之外**没有**别的工具会给行 id（`page_markdown_get` / `block_get` 的返回里都没有 `row_id`）——
拿不到时用 `md:p<页号>`：宿主会把它挪到该页对应的正文行上（见 `annotations.py` 的 `locate_in_rows`）。
**不要自己编 `p009-08` 这种行 id**：编出来的行 id 定位不上，高亮就悄悄没了。
**原 PDF 那一面只能查不能建**：它的文字层在阅读器的 pdf.js 里，服务端算不出偏移量 ——
要标那儿就让用户在 PDF 页上自己划词，你负责解释与写笔记。

### 默认标译文面（中文）

用户口径（2026-12-06）：**优先给中文加高亮**。读者平时看的是译文那一列，而高亮只画在它所属的
那一面 —— 标在英文原文面的高亮，用户在中文视图里**根本看不到**（"笔记在列表里、正文一片白"
就是这么来的）。所以：

- **不要显式给 `side`**：宿主按文字自动判（中文 → 译文面；公式 → 译文面）；
- 要给就写 `zh` / `en`（只有这两个是准的；`original` / `translation` 只做归一化，别依赖）；
- 只有用户明确说「我在读英文原文」时，才用 `en` 并且拿英文原文来标。
- **历史数据里可能有 `side=en` 的高亮**（旧默认行为）：那不代表现在的口径，看到旧数据
  不要跟着把新标注也标到原文面；用户抱怨「高亮看不到」时，先看它是不是落在了 `en` 面。

中文原文从 `translate_get` / `page_markdown_get` 的译文侧拿；别自己补标点或改空格。

### 公式怎么标

公式**可以**直接标（2026-12-06 之前不行，别再用旧结论）：把公式的 LaTeX 原样作为 `text` 给它 ——
带不带 `$$` 都行，只给式子的一部分也认（至少 8 个字符）。坐标系里公式整体只占 1 个占位符，
宿主会把 LaTeX 换成那个位置，前端据此把**整个公式节点**包起来（块级公式连外接框一起）。

```
highlight_manage op=create anchor=p016-17 text="$$D(B) \geq 2^{-2B/d}$$"
```

**不要**因为"公式不是文字"就退回去标引出它的那句话 —— 那样笔记挂在一句旁白上，用户点开看到的
不是公式本身。真找不到时工具会回"最像的原文"，照着 LaTeX 再改一版。

### 图注 / 表注也能标，而且能挂笔记
图注就是页面里的一行正文（图 1 = `p007-06`、表 1 = `p009-01` 这类，`figure_list` 会给行锚点），
**能标高亮，也能在它上面写笔记**。带行内公式的图注（`TURBOQUANT$_{\text{prod}}$`）整条标也没问题：
落库的文字在公式那处是留空的（回执里的 `warning` / `text_note` 会说），界面上公式元素照样被整块包进高亮。
真要在笔记里写出那两个下标，就先 `page_image_get` 看原版面，再把下标写进笔记正文。

## 配色：两级 —— 先定色系表类别，再在色系里差深浅

用户口径（2026-12-07 修正）：**颜色表达语义，不是「每条都不一样」**。上一版要求逐条换色，
标到 20 条以上就崩了：七个色名不够用，公式线和结论线只能靠色相硬凑，扫读时分不出
「这是公式、那是结论」。现在的规矩是**两级**：

| 类别 | 色系 | 可直接用的 hex |
|---|---|---|
| 公式 / 推导 | indigo | `#6366f1` `#4f46e5` `#818cf8` |
| 定理 / 结论 | emerald | `#10b981` `#059669` `#34d399` |
| 术语 / 定义 | violet | `#8b5cf6` `#7c3aed` `#a78bfa` |
| 存疑 / 待核 | amber | `#f59e0b` `#d97706` `#fbbf24` |
| 错误 / 待办 | rose | `#f43f5e` `#e11d48` `#fb7185` |

- **第一级定色系**：同类别用同一个色系（全篇一致），用户扫一眼就知道这一片是公式还是结论；
- **第二级差深浅**：同一色系里条目多了就换深浅（indigo-400/500/600 这种），**不要**为了「不一样」
  跳到别的色系去 —— 那是把语义让给了随机配色；
- 同一类别的条目**允许同色**（两条都是「公式」，都 indigo 没问题）；跨类别才必须不同；
- 动手前先 `highlight_manage op=list` 看这篇已经用过哪几套色系，**跟着已有的走**，别一篇里两套；
- **颜色代码自己给**：`#6366f1` / `rgb(99,102,241)` / `hsl(239 84% 67%)` 都原样存下并画出来，
  常见色名（indigo / emerald / violet / amber / rose …）也认；不传时宿主挑当前用得最少的兜底，
  但别指望它替你表达语义。

## 批量：一次标一批 / 记一批

用户一口气要十几处（"把这些术语都标出来，每条配一条笔记"）时**不要一条一来回**：
`op="create"` 改传 `items`，一次建一批。

```
highlight_manage op=create items=[
  {"anchor": "md:p5", "text": "随机旋转", "color": "indigo"},
  {"anchor": "md:p6", "text": "残差量化", "color": "teal"}
]
note_manage op=create items=[
  {"highlight_id": "h-…", "content": "这里的 prod 指内积误差那一支"},
  {"highlight_id": "h-…", "content": "与式 (3) 同一个口径"}
]
```

- 每条可以带自己的 `anchor` / `text` / `color` / `side`；没给的用顶层的默认值。
- 回执是**逐条**的：`created` 里是建成的（带 id、页码、命中原文），`failed` 里是没建成的
  （带原因与"最像的原文"）——**照着 `failed` 只补那几条**，不要整批重来。
- 一次最多 24 条；要标更多就分批（每批之间可以先 `op=list` 核对一下）。
- 笔记要挂在刚建好的高亮 id 上：先建高亮、**看回执拿到 id**，再建笔记（同一个回合里连着做）。

## 检索笔记与高亮：`notes_search`

`op=list` 是「这一篇现在有什么」（逐条列），**`notes_search` 是按关键词找**，两者别混：
用户问「我记过关于…吗」「哪条笔记里提到…」，用 `notes_search`。

```
notes_search(query="量化误差", scope="paper")        # 本篇
notes_search(query="量化误差", scope="all")          # 整个库（跨论文）
notes_search(query="量化误差", kind="notes")         # 只要写过笔记的
notes_search(scope="paper")                          # 不给关键词 = 看最近的那些
```

- **`query` 同时过滤两处**：用户**选中的原文**（`selected_text`）与**用户写的笔记正文**（`note`）。
  所以「我记得笔记里提到过 KL」和「我标过讲 KL 的那句」都能命中。
- `kind`：`all`（默认，笔记 + 高亮 + 批注）｜`notes`（只有写过正文的）｜`highlights`｜`annotations`。
- `scope`：`paper`（默认，当前这篇）｜`all`（整个知识库，结果带 `paper_id`）。
- **几个关键词一次给**：`notes_search(queries=["量化误差", "KL 散度"])` —— 回执按词分组（`groups`），
  别一个词一来回。标图注前确认位置时同理：`figure_list(pages=[7, 9])`、
  `figure_image_get(items=[{"page": 7, "index": 1}])` 都是一次给多条。

### 回执里两个字段别读反

| 字段 | 是谁说的 |
|---|---|
| `selected_text` | **论文的句子**（用户选中的原文） |
| `note` | **用户自己写的话** |

回答里必须分清：把 `selected_text` 当成「用户笔记」就是张冠李戴。

**`note` 为空不是「正文丢了」**：它只表示「这条高亮上本来就没写过笔记」。要看写过笔记的那些，
用 `kind="notes"`。工具回执里的 `hint` 说的就是这件事。

跨库（`scope="all"`）命中的别的论文，**你并没有读过那篇**：只能按回执里的片段说「某篇里记过 X」，
并给出论文标题与页码，不要复述细节、不要替它下结论。
## 三条硬规则

1. **`text` 必须逐字一致**，但**记号不用你手工剥**：`**重点**` 与 `重点` 两种写法都认
   （宿主会把 `**` / `__` / 反引号这些 Markdown 记号忽略掉再匹配，行内换行按排版接回）。
   **公式那处留空也认**：`$x$` 给 LaTeX、给 `$x$`、或者整句里公式位置空着，都能落上。
   找不到时工具会回"最像的原文"，照着改一版再试 —— 不要瞎猜、也不要自己编偏移量。

   ⚠️ **写含常数的笔记前，先看页图**（`page_image_get`）。转录里的 LaTeX **不可靠**：
   `\sqrt{3}\,\pi^2` 与 `\sqrt{3\pi^2}` 在转录里会是同一串字符（根号覆盖到哪儿的信息丢了），
   抄错一个常数就把结论写反了。**只做概念性说明的笔记**才可以只凭转录；
   凡是笔记里出现**数值、常数、上下标、括号范围**这类会改变结论的符号，先对页面图再写。
2. **写之前先看**。"标这段"要先知道它在哪一面、哪一行（`paper_search` / `page_markdown_get`）；
   "给高亮加笔记"要先 `highlight_manage op=locate` 确认那条高亮是用户说的那一条
   （同一段文字可能出现多次，靠 `occurrence` 区分）。
3. **标错位置先「挪」，不要删了重建**（2026-12-07 补）：
   `highlight_manage op="update" highlight_id="h-…" anchor="md:p6"`（+ 可选 `text`）——
   宿主在**新锚点**重新定位同一段文字，**id 不变、笔记跟着走**；新锚点那边找不到就报原因，
   什么都不改（不会留"挪了一半"的状态）。只有"这条根本不该存在"时才用 `op="delete"`。
4. **删除是高危动作**：只在用户明确说"删掉"时做，且必须 `reason` 写清是哪一条；
   删高亮会**连带删掉它挂的笔记**（锚点没了笔记就成了死数据）——做之前说清后果。

## 回执里那两句提醒

- `overlap`（或 `warning` 里）出现「与你已有的 N 条高亮重叠」：说明这里**已经标过**。这不等于
  失败，但要在回答里说一声，并把新旧两条核对一下 —— 压在一起有时是你要的（强调 + 术语），
  更多时候是手滑，那时用 `op="delete"` 删掉多余的那条。
- 笔记回执里出现「已经有很像的笔记」：那条内容与已有笔记**几乎相同**。别写重：要改就去
  `note_manage op="update"` 改那一条，或者在回答里说明两条的区别。

## 回答怎么写

标完 / 写完，用一两句话交代**位置**：第几页、哪一面、标的是哪段文字（引一小段）。
别贴 id（`h-3f2a…` 这种对用户没意义），要贴就贴页码 + 原文片段。
