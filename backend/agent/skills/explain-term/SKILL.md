# 核对术语定义与译法

本技能负责核对论文术语的含义、缩写和译法。首先查找论文中的定义句，再检查项目术语档案中的已有记录。解释以本文定义和已确认的术语口径为依据。若通用译法、项目既定译法与本文用法不一致，应分别说明其适用语境，不将不同概念混为一谈。

## 术语有三个来源，按可信度排

1. **档案简报的「统一译法」**（8~20 条）：这是真正注入每次翻译 prompt 的那一份，是**全文口径**；
   同段还有「保持英文不译」，列的是不译的词。
2. **IR 术语表**（阅读器「术语」页签里那份，`GET /papers/<id>/glossary`）：解析/翻译阶段攒下来的，
   可能和简报不是同一批。页签里的条数是两者**按英文去重的并集** —— 所以「页签里有、简报里没有」
   是正常的，不要据此判断谁错了。
3. **正文自己的定义句**：缩写常常根本没进术语表（`SLB` 就是），这时必须从正文找。

## 流程

1. 先看档案的「统一译法」「保持英文不译」两段。答案能对上就直接用，不要另起一套译法。
2. 档案里没有该术语时，用 `paper_search` 找它**在文中第一次出现的定义句**（缩写通常在摘要或引言里展开）。
   一次问好几个术语就**一次给几个词**：`paper_search(queries=["QJL", "random rotation"])`，回执按词分组。
   缩写与全称都值得各给一个：正文里出现过「全称 (缩写)」句式时后端会自动双向扩展，没出现过的就两个都试
   （`QJL` / `Quantized Johnson-Lindenstrauss`）。
3. 想看它在译文里的实际说法，用 `translate_get(pages)` 取那几页的中文，
   或 `page_markdown_get`（一次给原文 + 译文，便于对照）。
4. 回答格式：`英文原词（缩写全称）→ 中文译法 —— 一句话说明它在这篇论文里指什么`。

## 能写的是「检索变体」，不是「译法」

`term_manage` 维护的是**检索变体**：同一个概念在这篇论文里的另一种写法（下标写法 / 全称 / 缩写）。
它只影响检索排序，**译文一个字都不会被它改**。

    term_manage(op="add", items=[
        {"term": "TurboQuant_mse", "variants": ["TurboQuant MSE", "TURBOQUANT mse"]},
        {"term": "SLB", "variants": ["Shannon lower bound"]},
    ])

- **批量**：一次给几组，别一组一来回；回执按 `term` 分组，每组带证据 —— 加上变体**前后**分别带回
  哪些页、新增了哪几页（`gained`）。判好坏看**页集合的变化**，不要看条数（实测条数 0→8 很好看，
  但定理 1 那条仍然没回来）；
- `op="list"` 看已经登记了什么（带 id），`op="remove"` + `ids` 撤销；
- **不要拿它改译法**：用户要「统一术语 / 换个译名」，那是 `page_markdown_edit` 逐页精准改（`find`
  在页内必须唯一、先读后写）；术语表（`zh`）本身 agent 侧仍然只读，让用户去阅读器「术语」页签编辑。

## 硬要求

- **区分「业界通用译法」与「这篇论文的用法」**。用户问的是后者；前者只在明显需要时补一句。
- 缩写展开必须来自论文本身，不要按你记忆里的写法填（同名缩写在不同领域含义完全不同；
  后端的自动扩展也只学正文里的句式，没有任何内置缩写表）。
- 译法**以档案的「统一译法」那一段为准**，即使用户习惯别的译法：回答里可以提一句「本文统一译作 X」。
- **术语表是一对一（英文 → 中文），不是同义词表**。正文里 `Online (data-oblivious) quantization`
  这种只是行文并置：`online` 往往就是普通形容词，把两个词当成同一概念的别名去讲会把释义说歪。
  检索层面可以用宽松变体，术语与译文层面不能。
- **你改不了术语表**：术语与「保持英文不译」只能在阅读器的「术语」页签里由用户自己编辑（那边有「编辑」按钮），
  agent 侧只有读。用户要改就告诉他去那儿改，不要假装写过，也不要把自己说过的译法当成已生效的口径。
- 不要为了凑数罗列一堆普通词（「model→模型」这种没有信息量）。
