# 讲清一个公式

先**把公式取出来**（`formula_get` 拿 LaTeX 与上下文），再讲清它在算什么：每个符号定义什么、这一项为什么出现在这里、它在整条推导里起什么作用。**不做推导步骤的复现** —— 用户要的是读懂这一条，不是从第一行推到最后一行。

## 什么时候用

- 这个公式（公式 (3)）是什么意思 / 它在算什么
- "这里的 $d_k$ 是什么？"
- "为什么除以 $\sqrt{d_k}$？"
- 若公式的 LaTeX 与原文对不上（乱码、缺项、上下标错位），也走这一套核对（见流程第 4 步）。

## 流程

1. **先定位**：不知道公式在哪一页就先 `paper_search`（公式旁边的正文句子通常搜得到，
   比如 "scaled dot-product attention"）。**公式本身很难被检索命中**（LaTeX 与自然语言不同空间）。
2. `formula_get(page=…)` 拿公式。**默认给的是页级 Markdown 里的块级公式（`display=true`）**
   —— 就是阅读器「公式」栏里看到的、可以整条复制的那批完整公式，按文档顺序排好。
   - **默认只给块级那批（实测 24 条）；正文里另有 300 多条行内公式**（`d_k`、`b-1`、
     `_{\text{mse}}` 这类）。回执的 `display_total` / `inline_total` 就是这两个数；
   - 要看**行内符号**：用 `page_markdown_get` 读那一页正文看上下文，或显式传
     `include_inline=True`（行内公式也列出来，更全也更碎）；
   - **行内公式不适合当引用编号来源**（碎片多、位置散在正文里）：引用请用块级那批；
   - `truncated=true` 说明超过 40 条：**`missing_pages` 直接写着还差哪几页**，
     照它 `formula_get(page=…)` 补（不要自己把条数按页数一遍）；先看 grade 高的（有的话）；
   - 同一条公式在**不同页重复陈述**时只出现一条，其余页码在该条的 `also_on` 里；
   - `source`：`markdown` = 页级正文的块级公式（默认，完整）；`parse` = 那一页没有块级公式，
     用了解析卡兜底；`mixed` = 两者混。**兜底条目的 LaTeX 可能只是公式的一段** ——
     `partial=true` 时用 `page_image_get(page)` 看那一页原版面（阅读器里同一位置也有公式裁图）。
3. 符号还是不清楚时，`page_markdown_get` 读那一页，找符号表 / 定义句。
4. LaTeX 明显可疑（缺项、上下标错位、乱码）时，用 `page_image_get(pages="5", dpi=300)`
   看原版面再核对 —— 这一步不要省，OCR 出的公式错得很有规律。
5. 讲解释时：**先说这个公式在算什么**，再逐符号说明，最后说它在整条推导里的作用。

## 硬要求

- **不要自己重写 LaTeX**。引用时逐字用 `formula_get` 返回的那一串；怀疑它错了就说
  "识别结果可能有误，原版面是……"。
- 符号含义**以论文自己的定义为准**：同一个字母在不同论文里含义不同，不要按你的常识补。
- `formula_get` 返回的 `context` 是节选，句子可能被截断；要完整句子就用
  `block_get(refs=[…])` **一次展开那几个 ref**（有的话），或读那一页。
- `formula_get` 本身**不必按页批量**：不传 `page` 就是整篇的公式（超过 40 条才截断），
  所以"先看全篇再挑"和"按页看"各一次就够。要看几页的**正文**才用 `page_markdown_get("4,7")`。
- 公式里出现论文自定义的算子（如 $\text{MultiHead}$）时，去正文找它的定义式再解释，
  不要望文生义。
