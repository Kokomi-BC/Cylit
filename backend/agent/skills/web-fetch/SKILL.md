# 读一个网页的正文

还不知道该读哪一篇时，先 `web-search` 拿候选结果；这个技能负责**把已经选中的那一篇读下来**。

## 什么时候用

- 用户直接给了一个链接，让你看看里面写了什么；
- `web-search` 的结果里某一条正是要的依据，但摘要（截到约 400 字符）不够判断；
- 需要核对某一页上的具体表述（数字、版本号、日期、措辞）。

## 怎么用

`web_fetch(url, max_chars)`：

- `url` 用 `web-search` 返回的那一串原样传，不要自己拼；
- `max_chars` 合法区间 **500~200000**，不传就用设置里的默认（6000）。返回里 `truncated=true`
  说明只保留了前面一段，后面的内容确实需要时再调大重抓一次。

## 不要抓

搜索结果页、站点首页、要登录才能看的地址 —— 这些要么没正文，要么取回来是一堆导航文字。

几次要看可以**一次给**：`web_fetch(urls=["https://a…", "https://b…"])` —— 并发抓（最多 3 篇同时、
每篇 25 秒超时、一次最多 6 篇），某一条打不开只在那一条上给原因，别的照常返回。
但**别为了"多抓点没坏处"**：正文很占上下文，抓五篇等于把前面读到的材料全挤掉 ——
上限是防呆，不是鼓励。

## 引用纪律

- 外部网页不是论文原文：引用必须写 `[标题](链接)` 并带上站点名，用户要能自己点过去核对。
- 论文里的论断不能拿网页来支撑；也说清哪一句来自网页、哪一句来自论文。
- 不要给网页内容编 `[n]` 编号（编号只属于论文里的材料）。
