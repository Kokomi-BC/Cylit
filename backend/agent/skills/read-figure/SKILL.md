# 读图

## 什么时候用

- "图 3 说明了什么？"
- "这张图里精度随位数怎么变？"
- "表 2 里哪个方法最好？"
- 用户贴了图号，或问的是"示意图/流程图/架构图"里的细节。

## 流程

1. **定位**：不知道图/表在第几页就先 `paper_search`（图注文字通常搜得到，比如
   "Figure 3:" / "Table 1:" 后面的描述）。图注是**最可靠的定位线索**。
2. `figure_list(page)` 看这一页有哪些**图形区域**（插图与表格都在这里，看 `kind`），
   拿到 `index`。
3. `figure_image_get(page, index)` 把这一区域交给视觉模型看 —— 曲线趋势、标注、图例
   这些**只能看图**，正文里往往没写。
4. 需要文字佐证时再 `page_markdown_get` 读那一页（图注 + 正文对该图的讨论）。
5. 回答里要配图就**逐字**用 `figure_list` 返回的 `image_url` 写 `![说明](url)`。

## 表格（`kind="table"`）

- **先看读页给的表格**：转录过的页里，表是规整的 Markdown 表格（`| 方法 | KV Size | … |`）
  —— 这是事实源，直接照格读取，不要舍近求远去截图。
- 只有**没转录过**的页才会看到"单元格粘连"的正文（`1645.2945.16` 其实是 `16 | 45.29 | 45.16`），
  列对齐已不可恢复：这时才 `figure_list(page)` → 找 `kind="table"` 那条 →
  `figure_image_get(page, index)` 看表图。
- 表图是**同一页区域裁图**，比整页 `page_image_get` 清楚得多，也便宜：**读表格一律优先它**，
  整页图留给版式与上下文（想知道表在这页的什么位置、旁边还有什么时）。
- 逐行读表容易串行：读到的数值要说清"行（方法名）+ 列（指标名）"再下结论；
  表太大（几十行）时只回答用户问的那几格，不要整表复述。
- 表格的**文字结论**（"在 4× 压缩下仍接近全精度"）通常正文里就有，
  数值用表格、结论用正文，两者对得上再写进回答。

## 硬要求

- **不要从图里读具体数字**（"大约 92%"）：刻度目测不可靠。需要数值就去正文或表图找，
  找不到就说"图里显示趋势上升，正文没有给出具体数值"。
- 一张图被切成多段（跨页/中间夹了别的图注）时，`figure_list` 会给多条，看图时要意识到
  它们可能是同一张图的不同部分；回答里说清楚你看到的是哪一段。
- 图注与正文冲突时以正文为准，并指出这个不一致 —— 这往往正是用户想知道的。
- 视觉模型也可能看错。把握不大时用"图中显示…"这样的措辞，不要写成断言。
