# 译文核对

比对**原文与译文**：是不是等价、覆盖是不是完整、术语有没有跑偏。

用户只是「想读这段中文在讲什么」时走 `read-text`（读正文）；这里只做**核对**。

## 什么时候用

- "这句译文对不对？"
- "这段中文怎么这么别扭？"
- 若译文与原文对不上（漏译、多译、公式被改写成文字），也走这一套核对。

## 流程

1. `page_markdown_get(pages)` 一次拿到**原文 + 译文**（对照着看，不要分两次取）。
2. 需要更细的中文时用 `translate_get(pages)`（只回译文，逐块带 ref）。
3. 逐句判断三件事：**有没有漏**（原文一段译文中消失了）、**有没有加**（译文中出现了
   原文没有的断言）、**术语是否与档案 `glossary` 一致**。
4. 公式、符号、引用编号要**原样保留**：译文里把 `$d_k$` 译成"d k"、把 `[12]` 删掉，
   都算错误。
5. 报告要给**具体位置**（第几页、哪一句），并给出建议改法；不要只说"整体还行"。

## 硬要求

- **译文是派生物，原文才是事实源**。判断对错以原文为准，不要因为译文读起来更顺就认可它。
- 译文里的错误**不要顺手改写成对的再引用**：引用时用能代表原文的表述，并指出译文的问题。
- 用户**明确要求改掉**那处译文时，走 `edit-text`（`page_markdown_edit`）：先读、再改、
  改完逐条报告；没被要求就只在回答里指出问题，**不要动手改**。
- 这一类问题通常**不需要跨库检索**，别去调 `kb_search`。
- 只凭译文无法判断时（原文那一页没解析好），用 `page_image_get` 看原版面。

## 回答格式

结论在前（"译文基本准确，但有两处问题"），然后逐条：位置 → 问题 → 建议。
