# 分块方案（已实施）：TOC 层级 + 页级行原子 + LLM 语义锚点

> 状态：**已实施**（默认路径 `kb.chunk_mode=rows`）。实测数字见 `docs/dev-log.md` §17.63。
> 相关代码：`backend/services/knowledge/chunking.py`（新分块层）、
> `backend/services/knowledge/knowledge_service.py`（索引层）、
> `backend/services/translation/page_translate.py`（`breaks` 契约与校验层）、
> `backend/services/paper/reader_service.py`（读时把锚点落到行上）、
> `tests/test_kb_row_chunking.py`、`tests/test_semantic_breaks.py`。

## 0. 一页纸

```
pages.json 的每一行（原子：en=original / zh=translation）
      +  阅读器目录（宏观边界：TOC 节点之间不许因为长度合适而合并）
      +  LLM 语义锚点（节内边界：转录时给出的 `breaks`，见 page_translate）
   ↓ 确定性组装（target 软阈值 / hard 硬上限 / 父节引言并入首个子节）
   ↓ 校验层（覆盖一次、顺序不变、不跨节、≤ hard、公式表格完整）—— 不通过就退化
final chunk（正文由行**重新拼装**，绝不重新生成）
```

三条硬约束（设计时就量过，见 §17.63 一）：

1. **行是唯一内容来源** —— 两侧同一批行、逐行对位；没有"块↔行按比例对齐"那一层；
2. **单行永不超 hard**（实测 max 1487 < 2240）⇒ 超长单元只能由多行合并而来，
   回退动作就是"退回行边界"，**公式 / 表格 / 图注不可能被切断**（可证明，不靠模型自觉）；
3. **semantic unit ≠ final chunk** —— LLM 只回答"这里是不是自然边界"，切多大多小由代码定。

## 1. 三个部件

### 1.1 TOC（宏观边界）

`chunking.section_tree()` 取 `reader_service.build_outline()`：页级**标题行** + **章节编号**推层级
（`_apply_semantic_levels`），与阅读器左侧目录同一份数据。实测 24 / 27 个节点全部能定位到行。

为什么不用解析侧 Markdown 标题（`md/full.md` 的 `#`）：

- **漏标题**：turboquant 漏 `2.4 NEAR NEIGHBOUR SEARCH`，attention 漏 `3.4 Embeddings and Softmax`
  与 `6.2 Model Variations` —— 漏掉的节被静默并进邻节，`section_path` 跟着错；
- **多假标题**：算法框行 `6: r ←x −DEQUANT(idx)`、图内文字 `*PyramidKV Score: 0.981*`、
  表行 `GNMT + RL [38]` 都被标成 heading，进了旧索引的小节名。

### 1.2 行（内容原子）

`chunking.row_units()`：`pages.json` 的行 → `{id, page, index, type, original, translation,
section_path, section_kind, semantic_break, structural, skip_reason}`。

跳过（与改造前口径一致）：参考文献**整节**（行类型 `ref`，或所属节点标题是 REFERENCES ——
turboquant 的条目行是 `para`，实测 77 行）、前沿元数据、空行。
没有页级产物（未翻译论文）时用**解析块合成行**（一块一行，与前端 `usePageRows.rowFromBlock` 同语义）。

### 1.3 语义锚点（节内边界）与它的校验层

转录提示词要求模型在同一次回复里给出 `breaks: ["<新单元开头那块的起始原文片段>", …]`。
`page_translate.apply_semantic_breaks()` 把锚点落到**行边界**上，逐条验证（九条判据见 dev-log §17.63 二），
**任何一条不合法只丢它自己**；`unmatched` / `ambiguous` 一律拒（猜错比少一条边界坏得多）。

为什么用结构化字段而不是内联 `<!-- @semantic-break -->`（用户拍板）：结构化锚点天然不可能写进
公式 / 表格内部，而且每条都能确定性校验"是否落在真实块边界上"；不一致率本身是可观测的质量指标。

## 2. 组装规则（`chunking.assemble`）

0. **断点是块的硬边界（`break_walls`，默认开）**：任何一条 chunk 内部（首行之外）都不许出现
   本路的断点行。也就是说"块从断点开始"，不只是"单元从断点开始"。
   没有这条约束时，模型给的锚点只把**单元**切细（实测 2~2.6 倍），随后又被下面第 1/3 条
   的合并规则吞回去 —— 实测同一份文本只切 `use_breaks` 开/关，块集合**一字不差**、
   跨断点块 27 个（turboquant 路 a）。模型没给锚点时这条规则恒不触发，落点与改造前一致。
1. 一个 TOC 节点的**整棵子树**能装进 `target` **且内部没有断点** → 整棵成一块
   （`2.2 Needle`、`D Additional Experiment` 这类）；
2. 否则节点自己的行成一块（它内部有断点就先按断点切片，每片各自成块）；短于 `floor` 且有子节点
   → **并进首个子块**（祖先→后代，唯一允许的"跨界"；兄弟之间永不合并）；但**目标块的首行
   是断点时不合并** —— 合并会把断点挤到块内部，宁可让引言自己成块（计入 `intro_alone`）；
3. 同一节点内：先按语义单元切，再贪心累加到 `target` 之上即封口，`current + next > hard` 必停；
4. 单个单元自身 > `hard` → 退回**行边界**继续切（单行 < hard，所以不会切进公式/句子中间）。

参数仍然是 `kb.chunk_target_chars` / `kb.chunk_min_chars` / `kb.chunk_hard_chars`（默认 1400 / 200 / 2240），
不新增第二套配置。

## 3. 校验层（`chunking.validate`）

| 不变量 | 判据 |
|---|---|
| 覆盖 | 该进正文的行**恰好一次**（缺行/重复都报出来） |
| 顺序 | chunk 内行下标递增，chunk 之间不交叉 |
| 不跨节 | 一个 chunk 的行不落在两个**不可比**的 TOC 节点里（祖孙关系不算跨界） |
| 长度 | 英文侧 ≤ hard（单行超限只告警，因为一行不可拆） |
| 结构完整 | 正文块里不出现表格行 / 图注行 / 参考文献行 |

不通过 → 先退回"不用锚点"重装一次（`use_breaks=False`）→ 仍不通过则原样入库 + `log.error`。
**宁可入库也不静默丢内容**，这是"LLM 输出不能直接进 LanceDB"的落点。

## 4. 图 / 表 / 公式

- **图 / 表**：结构行（`caption` / `table` / `figure`）按"同页 + 同图号"归组 → 各自一条 chunk，
  正文 = `表格 1：<图注>` + **表体 markdown**（旧路径英文侧一条表体都没有）。
  图注与表体的配对**与图注在上还是在下无关**（实测两种排版都有）。
  只有 **IR 认证过**的图注行才算结构行（`Table 2 summarizes our results…` 这类是正文）。
- **公式**：仍来自 canonical 清单（`reader_service.markdown_formulas` → C 口径 → 挂锚点），
  只是章节与排序改用"它所在的行"；正文里公式原样留在行文本中。
- **REFERENCES**：整节不入库（用户口径 §11，不因为锚点而改变）。

## 5. 开关与回退

| setting | 默认 | 作用 |
|---|---|---|
| `kb.chunk_use_breaks` | `1` | `0` = arm2（只按 TOC 切，忽略锚点），用来量锚点到底带来多少 |

`break_walls` 是 `chunking.assemble` / `chunking.build` 的参数（默认 `True`），不走 setting：
它没有"生产上可能想关掉"的理由，只是回退与对照实验的把手（`break_walls=False` 就是旧合并口径；
`use_breaks=False` 会把墙一起关掉，对照臂不受影响）。

> 旧路径（解析块 + 按比例取译文）**已删除**（dev-log §17.64，净减 760 行）：
> 它曾经挂在 `kb.chunk_mode=block` 上作为回退，但 A/B 已经证明新路径全面更好，
> 留着只会让"两侧同源"这个不变量出现第二个实现。要复现它请用
> `tests/retrieval_regression/build_baseline.py`（从指定 git revision 取旧代码建索引）。

A/B 用法：改 setting → `python cli/pr.py index <paper> --rebuild` → 跑
`python -m tests.retrieval_regression.run --out …`（题库 30 问，单题可用 `paper_id` 覆盖论文）；
两臂一体跑完用 `python scripts/kb_arm_compare.py`，只看"锚点改变了什么"用
`python scripts/kb_anchor_effect.py`。

## 6. 已知结论与下一步

- **收益主要来自 TOC + 行原子**：30 问里正文命中 90% → 97%、正文 MRR 0.808 → 0.901、
  语义块含公式 70% → 90%，逐题"新增命中 2 / 更好 4 / 更差 0 / 丢失 0"。
- **锚点这一轮没有净收益**（arm2 → arm3：0 更好、1 更差），但它确实改变了分区
  （turbo 切点不同 30 个、attention 只有 2 个；被迫按行切的块 12 → 1）。
- **为什么没换来指标**（`scripts/kb_anchor_effect.py` 量出来的）：
  ① 锚点是**段落级**（校验层明确拒绝句中/公式内），不是句级，实测语义单元中位 2 行；
  ② target=1400 下 **turbo 43% / attention 57% 的锚点被吞进块内**（没成为切点），
     target 调到 500 时被吞比例才降到 24% / 53%；
  ③ attention 的小节本来就 ≤ target → 走"整棵子树成一块"分支，锚点无处可施（target=900 时切点差 0 个）；
  ④ hit@6 已 97%，答案段落在两臂里都落在同一个块内 —— 指标看不见边界挪动一个段落。
- **下一根杠杆**：把 target 调细（600~900）；更根本的是让**语义单元本身可检索**
  （small-to-big：单元当检索单元、父节当上下文），或检索侧按单元做邻居扩展 ——
  在 1400 字的大块里，句级/段落级语义本来就没有可检索的落点。
- **硬边界（2026-12 补）实测**（`python scripts/kb_break_walls_compare.py`，本地库 5 篇）：

  | 论文 · 路 | 本路断点 | 块数（关 / 开） | p50（关 → 开） | 跨断点块（关 → 开） | 纯标题块 | 校验 |
  |---|---|---|---|---|---|---|
  | turboquant · a | 63 | 45 → **72** | 1569 → 778 | 27 → **0** | 1 → 1 | ok |
  | turboquant · b | 9 | 31 → **35** | 1070 → 817 | 2 → **0** | 1 → 1 | ok |
  | 其余 3 篇（0 断点） | 0 | 不变 | 不变 | 0 → 0 | 不变 | 不变 |

  结论：硬边界把"块"真正交回给模型（跨断点块 27 → 0），代价是块数 +60%、中位长度腰斩
  （1569 → 778，仍 > floor=200）；没有断点的论文**逐字不变**，纯标题块没有增加。
  这也顺带回答了 §6 的第 ② 条：**锚点被吞进块内的比例现在是 0**（不再是 43%）。
- 待办：重译后 attention 的那 1 条 `Highlight`（行 id `p009-06`）需要人工核对；
  题库继续扩容（30 → 50）以便对"锚点/target"这类细粒度改动有区分度；
  按 §6 的下一根杠杆做 target 网格实验，或直接上"语义单元当检索单元"的 small-to-big。
