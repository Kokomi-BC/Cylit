# 身份模型（row 的稳定身份 pid）

> 起因：标号跳不准、同一处证据两枚标号、短码重建后漂、`row-`/`blk-` 前缀到处翻译 ——
> 这些不是五个 bug，是**没有稳定身份**的五个症状。加规则只能止痛，这里定身份。

## 1. 现状：五套派生 id，互相翻译

| id | 由什么派生 | 谁在用 | 一变就坏什么 |
|---|---|---|---|
| 行 id `p015-06` | 页号 + 页内序号 | 页级产物、阅读器 `data-row-id`、chunk `row_ids` | 页内插入/合并一行 → 后面所有行换号 |
| 解析块 id `turboquanton-p03-b16` | 解析顺序 | 块表、`block_rows`、agent 工具 | 重解析 → 全变 |
| chunk id `…:a:unit:p015-06-p015-06:en` | 首块-末块 + 路 + 语言 | 检索、解读、引用 | 重切分/重译 → 全变（所以要 `stale_refs`） |
| 短码 `A116` | 材料清单序号 | 解读正文 | 清单顺序变（并列、重切分）→ 换号 |
| `row-` / `blk-` / `fig-p…` | 前缀约定 | 前端 + 部分后端 | 谁认识谁不认识（`_anchor_page` 曾只认 md/pdf） |

派生身份 ⇒ 上游任何变化都让旧引用失效 ⇒ 每层都要一张翻译表。
已为此打的补丁：`normalize_block_id`、`resolve_anchor`、引用按落点去重、`merge_ref_codes`、读取时补齐、
二级排序键、`row_less_blocks`、`stale_refs`、`base_id`、`_without_lang`。

## 2. 目标：pid 是唯一身份

```
pid（生成一次，永不重绑）
 ├─ 页级产物：每一行带 pid（id 仅作显示/检索粒度）
 ├─ chunk.metadata.pids（有序）/ 引用 / 解读 / 高亮 / 笔记 / agent 工具：**只存 pid**
 └─ 短码：每次解读的别名表（A0xx → pid），不再是身份
```

**pid 是 UUID，不是哈希。** 内容的指纹只用于**对齐**（重建时把旧 pid 续给新行），不参与身份：
- 用户改一个字（`page_markdown_edit`）→ pid 不变，引用不断；
- 重解析改变行切分 → 对得上的行继承 pid，对不上的新建，**绝不把旧 pid 重绑到另一段**；
- 对不上的旧 pid 进 `retired`，引用它的时候按"内容已变/已失效"提示，而不是静默跳错。

## 3. 存储：`data/papers/<id>/md/row_ids.json`（唯一在重建中不被删的目录）

调研结论：`block` 表、`ir.sqlite`、`md/blocks.json`、`chunk` 表都会在解析/建索引时被删或整体重写；
`data/papers/<id>/md/` 只被追加（没有任何代码删它）。schema：

```json
{
  "version": 1,
  "rows":  [{"pid": "r-3f2a…", "page": 15, "order": 6, "fp": "a1b2c3…", "created_at": "…"}],
  "retired": [{"pid": "r-9c1d…", "page": 15, "fp": "e4f5…", "retired_at": "…", "reason": "text-changed"}]
}
```

- `fp`：`rebind.text_fingerprint`（归一化文本指纹），只用于对齐匹配；
- 写入必须**原子**（临时文件 + `os.replace`），读取容忍缺失/损坏（空注册表即可，pid 现建现用）。

## 4. 挂钩点：唯一一个 —— `reader_service._finalize_page`

行的诞生点是 `pair_rows` / `pair_rows_by_blocks` / `coords.pair_rows_by_src`（三个），
但它们之后还有两步会**改行集合与编号**，必须排在 pid 之前：
`absorb_one_sided_rows`（重编 id）、`_rejoin_carried_rows`（删本页第 0 行并重编号）。

而**当前有两个出口**在算行：`page_products()` 与 `merged_page()`，都排在上述两步之后。
阶段 1 把这两处收敛成一个 `_finalize_page(paper_id, page, rows, *, b_pages)`，pid 只在这个函数里落：

```python
def _finalize_page(paper_id, page, rows, *, b_pages):
    pids = row_identity.assign(paper_id, page, rows)   # 继承 / 新建 / 退休
    for row, pid in zip(rows, pids):
        row["pid"] = pid
    return ...
```

继承算法（`row_identity.assign`）：① 同页 `fp` 精确命中 → 直接续用；② 剩余用 `difflib.SequenceMatcher`
按序对齐（与 `_sequence_pairs` 同口径），insert 区间新建、delete 区间退休；③ 全部对不上 → 全新 pid。
复用现成 `rebind.rebind_block_ids` 的骨架（阈值 0.72、临时占位、二次分配），把 bbox 换成 `(page, order, fp)`。

## 5. 谁存什么（阶段 3 完成后的终态）

| 层 | 存 pid | 存位置 id（仅显示/检索） |
|---|---|---|
| 页级产物行 | ✅ `pid` | `id` = `p015-06` |
| chunk metadata | ✅ `pids` | `row_ids` 保留一版供检索展示 |
| 解读 refs_json | ✅ `code → [pid]` | `page`（给人看） |
| 对话引用 citations | ✅ `pids` | `page` / `label` |
| 高亮 / 笔记 / 批注 | ✅ `pid`（新写入） | 旧数据 `block_id` 兜底 |
| 前端跳转 | 传 pid | 由 pid 解析出行/页 |

**回滚前提**：pid 一旦写进用户内容（高亮/笔记），回滚前必须先导出 `旧 pid → 新 pid` 映射。

### 阶段 6 的取舍（为什么不删五套伪前缀与 stale_refs）

原计划是「pid 贯通后把这些兼容机器删掉」，做到阶段 5 后判定**不该删**：

- 这些 id 是**已落库的历史数据**（高亮/批注/笔记的 `block_id`、旧 chunk 的 `row-` 锚点、图表的 `fig-p010-01`）。
  删掉解析层 = 老数据的高亮与批注**立刻失去页码**，而且补不干净（历史 `anchor_hash` 仍是旧式）。
- `stale_refs` 仍然必要：pid 能认回「内容还在」的引用，但内容**真被改写/删除**时仍要「按页跳 + 如实告知」，
  那是正确行为，不是历史包袱。
- 所以 `normalize_block_id` / `resolve_anchor` / `stale_refs` 定位为**长期兼容层**：新数据走 pid，老数据走它们。
  哪天决定放弃老批注的精确定位，再删。

## 7. 验收不变量（`scripts/index_audit.py` 增补）

1. 每个正文行都有 `pid`，且 `pid` 全局唯一（同一 pid 不得出现在两页/两行）；
2. `retired` 里的 pid 不得被复用；
3. 重跑解析/建索引两次，**同一段文本的 pid 不变**（可脚本化：两次读取对齐比对）；
4. `chunk.metadata.pids` 全部能在注册表里找到（阶段 2 起）；
5. 引用里的 pid 覆盖率 100%（阶段 3 起）。

## 8. 顺带记录的两个既有缺陷

- ✅ **已修（阶段 4）**：`Highlight.anchor_hash` 原来把 `block_id` 拼进哈希 → id 一变哈希就变，
  重译后按 anchor_hash 重定位实际从未生效。现在 **pid 优先**（`sha256(pid:start:end:side)`），
  拿不到 pid 才**逐字节**退回旧式（老哈希仍等价）。必须带 `side`：同一行的原文/译文共用 `block_id`。
- ⚠️ 保留：`PATH_VERSION` / `PAGES_VERSION` 只写不校验（`page_translate.py:2049/2074`）；
  pid 继承不能依赖版本号，必须依赖指纹对齐（现状如此）。

## 9. 运维手册（现在怎么用）

| 场景 | 要做的事 |
|---|---|
| 新论文首次建索引 | 什么都不用做（行自带 pid、chunk 自带 `pids`、解读自动写 `refs_json.pids`） |
| 存量论文补身份（**不重建**） | `python scripts/backfill_ref_pids.py <paper_id>`（先 `--dry-run` 看四个计数） |
| 重建索引 | 引用靠 pid **自愈**，无需脚本；想让块级 `pids` 也对齐可再跑 `remap … capture` + `apply` |
| 巡检 | `python scripts/index_audit.py`（6 组：行覆盖 / 锚点 / 解读短码 / 索引卫生 / pid 覆盖 / 别名表）+ `python scripts/verify_pid_rules.py`（11 条注入实验） |
| 回滚一条数据 | 删掉 `refs_json.pids` 键即可（读路径退回 chunk id） |

### 顺序纪律（两次踩过的坑）

1. **`capture` 必须在重建之前跑**：它要读**旧** chunk 的 `row_ids` 才能把短码换算成 pid。
   先重建再 capture，capture 拿到的就是新块 → 后面的 `apply` 变成空操作，旧短码全部"过期"。
   正确顺序：`capture` → `index_paper(rebuild=True)` → `apply` →（可选）`backfill`。
2. **重新生成解读之后必须重跑 `capture`**：新解读的短码是**重新编号**的，而 `ref_pids.json` 里是
   旧短码 → pid 的映射。按 code 取值会把 A005 的 pid 写到另一段去（静默错配，比报错更糟）。
   正确顺序：`build_understanding(force=True)` → `capture` → `backfill`。
3. 两条命令都可以先加 `--dry-run`：`backfill` 会打印「来自 capture / chunk / inventory / 跳过」四个数，
   `apply` 会打印「集合相等 / 交集 / 未映射」。**未映射**属正常（旧短码指向的行可能已不存在），
   它们保留旧值、按"过期引用（可跳页）"处理，不硬凑。

## 10. 重切行之后：槽位 + 后继（2026-12-05 补）

一次真实事故（为了让中文侧也有语义锚点，重译了 turboquant 的 B 路附录页）把这条设计的**盲区**
打了出来，结论写在这里，别再踩：

**重译会重切行，而不是只改文本。** 块模式的 B 路按 A 的 block 配对，于是"原来那一行"被切成
两三行。旧 pid 只能退休，而引用唯一的跨重建桥就是 pid —— 11 条引用当场断桥。

**为什么原先找不到后继。** 退休记录只有 `fp + page`（连 `order` 都没有），而重切之后旧指纹与同页
任何活行的相似度只有 **0.40~0.54**（实测 4 条样例：0.402 / 0.402 / 0.539 / 0.704）。`MATCH_THRESHOLD`
是 0.72 —— 不是阈值调得不对，是"原来那一行"**不再作为实体存在**，任何"最像的那一行"都是猜。

**现在的做法：记位置事实，不记猜测。** 退休条目登记

```
{"pid", "page", "order", "fp", "retired_at", "reason",
 "successor", "successor_similarity"}
```

- `successor` = **同一槽位（page + order）上现在是谁**，不是"最像的那一行"；
- `successor_similarity` 一并存下，让调用方判断可信度：
  `heal_pid` 只在它 ≥ `CHANGED_THRESHOLD`(0.5)（"行还在、文本变了"那条线）时才顺着映射跳；
- 顺着映射可以连跳（身份连着退休几轮），带 5 跳上限与环保护；
- 没映射 / 不可信时退回指纹搜索（存量记录就是这个形态），仍找不到就老实标 stale。

**推论（重要）：行级精确对"被重切"的行是不可恢复的。** 能恢复的是块级定位。所以别在重译后指望
引用 100% 精确到行；要 100%，就得保证**不重切**（例如重译只改文本、不换配对方式）。

**同时修掉的另一个缺陷：`semantic_break_side` 是单值。** 一条行只能记"哪一路标的边界"，两路都标时
后写的赢 —— 块模式合成那一步无条件写 `translation`，把 A 路的归属整片抹掉（实测 attention 的 A 路
边界一直只有 9 个，它自己有 36 个）。现在另存 `semantic_break_sides` 集合，`chunking.is_break` 以集合
为准，单值字段只为兼容存量产物保留。
