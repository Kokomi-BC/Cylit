# 身份模型（row 的稳定身份 pid）

> 起因：标号跳不准、同一处证据两枚标号、短码重建后漂、`row-`/`blk-` 前缀到处翻译 ——
> 这些不是五个 bug，是**没有稳定身份**的五个症状。加规则只能止痛，这里定身份。

## 1. 现状：五套派生 id，互相翻译

| id | 由什么派生 | 谁在用 | 一变就坏什么 |
|---|---|---|---|
| 行 id `p015-06` | 页号 + 页内序号 | 页级产物、阅读器 `data-row-id`、chunk `row_ids` | 页内插入/合并一行 → 后面所有行换号 |
| 解析块 id `turboquanton-p03-b16` | 解析顺序 | 块表、`block_rows`、agent 工具 | 重解析 → 全变 |
| chunk id `…:a:unit:p015-06-p015-06:en` | 首块-末块 + 路 + 语言 | 检索、解读、引用 | 重切分/重译 → 全变（所以要 `stale_refs`） |
| 短码 `A116` | 材料清单序号 | 解读正文 | 清单顺序变（并列、重切分）→ 换号 |
| `row-` / `blk-` / `fig-p…` | 前缀约定 | 前端 + 部分后端 | 谁认识谁不认识（`_anchor_page` 曾只认 md/pdf） |

派生身份 ⇒ 上游任何变化都让旧引用失效 ⇒ 每层都要一张翻译表。
已为此打的补丁：`normalize_block_id`、`resolve_anchor`、引用按落点去重、`merge_ref_codes`、读取时补齐、
二级排序键、`row_less_blocks`、`stale_refs`、`base_id`、`_without_lang`。

## 2. 目标：pid 是唯一身份

```
pid（生成一次，永不重绑）
 ├─ 页级产物：每一行带 pid（id 仅作显示/检索粒度）
 ├─ chunk.metadata.pids（有序）/ 引用 / 解读 / 高亮 / 笔记 / agent 工具：**只存 pid**
 └─ 短码：每次解读的别名表（A0xx → pid），不再是身份
```

**pid 是 UUID，不是哈希。** 内容的指纹只用于**对齐**（重建时把旧 pid 续给新行），不参与身份：
- 用户改一个字（`page_markdown_edit`）→ pid 不变，引用不断；
- 重解析改变行切分 → 对得上的行继承 pid，对不上的新建，**绝不把旧 pid 重绑到另一段**；
- 对不上的旧 pid 进 `retired`，引用它的时候按"内容已变/已失效"提示，而不是静默跳错。

## 3. 存储：`data/papers/<id>/md/row_ids.json`（唯一在重建中不被删的目录）

调研结论：`block` 表、`ir.sqlite`、`md/blocks.json`、`chunk` 表都会在解析/建索引时被删或整体重写；
`data/papers/<id>/md/` 只被追加（没有任何代码删它）。schema：

```json
{
  "version": 1,
  "rows":  [{"pid": "r-3f2a…", "page": 15, "order": 6, "fp": "a1b2c3…", "created_at": "…"}],
  "retired": [{"pid": "r-9c1d…", "page": 15, "fp": "e4f5…", "retired_at": "…", "reason": "text-changed"}]
}
```

- `fp`：`rebind.text_fingerprint`（归一化文本指纹），只用于对齐匹配；
- 写入必须**原子**（临时文件 + `os.replace`），读取容忍缺失/损坏（空注册表即可，pid 现建现用）。

## 4. 挂钩点：唯一一个 —— `reader_service._finalize_page`

行的诞生点是 `pair_rows` / `pair_rows_by_blocks` / `coords.pair_rows_by_src`（三个），
但它们之后还有两步会**改行集合与编号**，必须排在 pid 之前：
`absorb_one_sided_rows`（重编 id）、`_rejoin_carried_rows`（删本页第 0 行并重编号）。

而**当前有两个出口**在算行：`page_products()` 与 `merged_page()`，都排在上述两步之后。
阶段 1 把这两处收敛成一个 `_finalize_page(paper_id, page, rows, *, b_pages)`，pid 只在这个函数里落：

```python
def _finalize_page(paper_id, page, rows, *, b_pages):
    pids = row_identity.assign(paper_id, page, rows)   # 继承 / 新建 / 退休
    for row, pid in zip(rows, pids):
        row["pid"] = pid
    return ...
```

继承算法（`row_identity.assign`）：① 同页 `fp` 精确命中 → 直接续用；② 剩余用 `difflib.SequenceMatcher`
按序对齐（与 `_sequence_pairs` 同口径），insert 区间新建、delete 区间退休；③ 全部对不上 → 全新 pid。
复用现成 `rebind.rebind_block_ids` 的骨架（阈值 0.72、临时占位、二次分配），把 bbox 换成 `(page, order, fp)`。

## 5. 谁存什么（阶段 3 完成后的终态）

| 层 | 存 pid | 存位置 id（仅显示/检索） |
|---|---|---|
| 页级产物行 | ✅ `pid` | `id` = `p015-06` |
| chunk metadata | ✅ `pids` | `row_ids` 保留一版供检索展示 |
| 解读 refs_json | ✅ `code → [pid]` | `page`（给人看） |
| 对话引用 citations | ✅ `pids` | `page` / `label` |
| 高亮 / 笔记 / 批注 | ✅ `pid`（新写入） | 旧数据 `block_id` 兜底 |
| 前端跳转 | 传 pid | 由 pid 解析出行/页 |

## 6. 阶段与回滚

| 阶段 | 内容 | 回滚 |
|---|---|---|
| 0 | 本文档 + `index_audit.py` 增「pid 覆盖率」检查（先允许 0 覆盖，标 not-started） | 无副作用 |
| 1a | `row_identity.py`（纯函数：指纹、继承、退休）+ 单测 | 删文件即可 |
| 1b | `_finalize_page` 收敛两个出口，行带 `pid`，payload 下发 `pid`（**无消费方**） | 删 `row_ids.json`，链路退回纯 id |
| 1c | 迁移脚本给存量论文生成注册表 + audit 覆盖率 100% | 同上（注册表是纯派生） |
| 2 | chunk 加 `pids`；新写入的引用/高亮/笔记带 pid | 旧字段仍在 |
| 3 | 读路径优先 pid，旧 id 降级为兜底 | 双读，可切回 |
| 4 | 短码改别名表（`A0xx → pid`） | 保留旧 `refs_json.codes` |
| 5 | 历史数据补 pid + 校验 | 备份 |
| 6 | 删除五套伪前缀 / `stale_refs` / `anchor_map` 翻译层 | — |

**回滚前提**：pid 一旦写进用户内容（高亮/笔记），回滚前必须先导出 `旧 pid → 新 pid` 映射。

## 7. 验收不变量（`scripts/index_audit.py` 增补）

1. 每个正文行都有 `pid`，且 `pid` 全局唯一（同一 pid 不得出现在两页/两行）；
2. `retired` 里的 pid 不得被复用；
3. 重跑解析/建索引两次，**同一段文本的 pid 不变**（可脚本化：两次读取对齐比对）；
4. `chunk.metadata.pids` 全部能在注册表里找到（阶段 2 起）；
5. 引用里的 pid 覆盖率 100%（阶段 3 起）。

## 8. 顺带记录的两个既有缺陷

- `Highlight.anchor_hash` 把 `block_id` 拼进了哈希（`annotation_service.py:85-86`）→ id 一变哈希就变，
  "重译后按 anchor_hash 重定位"（同文件注释）实际失效。阶段 2 换成 pid 后一并修。
- `PATH_VERSION` / `PAGES_VERSION` 只写不校验（`page_translate.py:2049/2074`），没有迁移逻辑；
  pid 继承不能依赖版本号，必须依赖指纹对齐。
