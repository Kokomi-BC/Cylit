Cylit 技能描述汇总（源：data/skills/*/SKILL.md，共 13 个技能）
==============================================================================

怎么用：只改每个块里的 description 和 正文开头 两个字段（冒号后面那一段整体替换即可），
别动 [NN] 编号、name、title 和 ==== 分隔线。改完说一声，我按编号写回各自的 SKILL.md。

字段说明：
  name        技能 id = 目录名，不要改
  title       技能正文的 H1 标题（给读者看的）
  description SKILL.md frontmatter 的 description —— 模型挑技能时看的就是这一行，
              必须单行、以「。」收尾；这段文字决定「什么时候会用到这个技能」
  正文开头    正文 H1 之后的第一段；若开头直接是小节，就取第一个小节（通常是「什么时候用」），
              多句用 ｜ 连成一行。改它 = 改技能正文开头的措辞

落地位置（两份，必须一起改）：
  data/skills/<name>/SKILL.md          agent 真正读的那份；data/ 不进 git，部署（git reset）不覆盖它
  backend/agent/skills/<name>/SKILL.md 进 git 的模板；新装/物化时从这里复制
  改完我两处一起写，再单独把 data/skills 那份推上线（prod 的 data/ 是它自己的一份）。

==============================================================================
name: answer-paper
title: 证据式论文问答
description: 回答跨段落取证的问题（核心贡献、方法原理、实验结论、局限、与相关方法的关系）：先检索再展开原文块，每个论断带编号；重搜最多两次，找不到依据就如实说没有，不用常识补论文没写的。
正文开头: 什么时候用这一套：问题是**跨段落的判断**，答案要由多处证据拼出来： ｜ "这篇论文的核心贡献是什么？" ｜ "它为什么用随机旋转？" ｜ "实验证明了什么、还能质疑什么？" ｜ "它和 XX 方法有什么不同？" ｜ 如果问题只是"某一页/某张图里说了什么"，不要走这套长流程 —— 直接读那一页或看那张图。

title: 论文精读
description: 精读一篇论文：先定文章类型与证据边界，再按「问题→缺口→方法→证据→机制→局限→复用」重构研究链；每条论断给定位，数值不猜、缺失不补；用户只问值不值得读时给一页结论卡。

name: read-text
title: 读论文正文
description: 按页读论文正文（英文原文 / 中文译文 / 两侧对照）：先定位到页，一次不超过 5 页，不连续的页一次给完；只读不改，按叙述连续复述而非逐块罗列，引用带编号，常数先对原版面。

[11] search-paper   ·   description 77 字   ·   data/skills/search-paper/SKILL.md
==============================================================================
name: search-paper
title: 论文检索
description: 在本文或整个知识库里检索，只回候选位置（页码、章节、短片段）不返回全文；先定位再引用带编号的正文，别的论文的片段只能说明某篇提到过，不能当自己读过的内容。
正文开头: 两个工具，先分清范围：paper_search(query, top_k, mode) —— **只在当前这一篇**里找。问「这篇怎么写的 / 为什么这么做 / 实验数字多少」都用它。 ｜ kb_search(query, top_k) —— 在**整个知识库**里找，结果会带 paper_id 与页码。问「我库里还有谁讲过这个 / 有没有别的论文提到 X」才用它。 ｜ **不要用 kb_search 回答「这篇论文怎么说的」**：那属于 paper_search，跨库检索会把别的论文的片段混进来。
